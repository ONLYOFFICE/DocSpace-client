# Dashboard (/dashboard) screenshot matrix

`packages/client/__tests__/dashboard-appearance.spec.ts` pins what the Overview
looks like to everyone who can reach it. The page renders no list of its own —
everything on it is decided by a handful of portal and user flags — so the spec
is a generated matrix rather than a set of hand-written cases.

## Axes

| Axis | Values | What it changes |
|------|--------|-----------------|
| role | owner, full-admin, room-admin, user, guest | profile-card pencil, plan line, create rights, guest restrictions |
| edition | SaaS, standalone | integrations card and Docs Connect exist in SaaS only; standalone is offered no SaaS billing at all |
| plan | SaaS: paid / free · standalone: community / enterprise / developer | plan line and apps subtitle name Startup or Business (SaaS only) |
| AI | on / off | AI Chat quick action, AI Agents card and sidebar item |
| Developer Tools | offered / limited to admins | Developer Tools and integrations cards |
| width | desktop 1440, tablet 900, mobile 390 | apps grid re-flows 4 → 2 → 1 |

The width axis is a block of its own (owner + guest, both AI states): what a
narrower window changes is the same for every audience, and what does interact
with it — how many cards there are — is covered by keeping both AI states.

## Where the frames live

```
screenshots/chromium/desktop/dashboard/
├── desktop/   {saas|standalone}-{plan}-ai-{on|off}-{role}.png
│               {saas|standalone}-devtools-limited-{role}.png
├── tablet/    ai-{on|off}-{owner|guest}.png
└── mobile/    ai-{on|off}-{owner|guest}.png  +  …-apps.png
```

The folder is the viewport, applied by the case runner from `viewport.key`; the
rest of the axes read off the file name. Mobile takes a second frame scrolled to
the apps grid — the page scrolls inside its own container, so one viewport frame
never reaches that far down and `fullPage` does not help.

## Rules the matrix encodes

- **A switched-off feature is absent; a feature that is not yours is visible but
  closed.** Portal switches (AI services, Developer Tools limited to admins)
  remove blocks outright. Lacking the rights leaves the content in place and
  refuses the action — a disabled control with an explanation, or a toast.
- Assertions cover both halves of every rule and hold on a local run;
  screenshots only compare truthfully in Docker (see `e2e-tests.md`).
- **Screenshot only where frames differ.** Standalone editions render alike
  (nothing on this page reads the `developer` flag, and standalone shows no
  billing), so Enterprise carries the full set and Community/Developer keep one
  canary each — `withScreenshot` on the case. Every case still runs every
  assertion. Prove equality by comparing frames pixel-wise before dropping any;
  a diff of a few dozen pixels at channel level 1 is antialiasing, not content.
- **The clock is pinned** (`FIXED_NOW`). Tariff and Docs Connect mocks answer
  with fixed calendar dates, so an unpinned frame silently becomes an
  expired-subscription one the day a date passes.
- The welcome modal is spent up front, under the signed-in user's real id — the
  flag is per-user, and a guessed id writes one nobody reads.

## Neighbouring specs

`dashboard-tour` walks the same page, so a card that appears or disappears
changes its step list too. `dev-tools-access`, `guest-restrictions` and
`integrations-dialogs` cover the behaviour behind the blocks this matrix only
sees the shape of.

## Regenerating

Baselines belong to whichever service can see the change: `tests-local` serves
the image's `dist`, so a source change needs `docker-compose build` first;
`tests-dev` mounts the sources instead. Both render identically — frames
generated by one pass on the other.

```bash
cd packages/client
docker-compose run --rm -T -e WORKERS=3 tests-local \
  pnpm exec playwright test __tests__/dashboard-appearance.spec.ts \
  --update-snapshots=changed
```

Then read the list of regenerated files: it is the cheapest review of what a
change actually did, and a frame you cannot explain is a finding. Revert frames
whose only difference is antialiasing — they are churn, not coverage.

`--update-snapshots=changed` rewrites only frames that differ, so an untouched
file means "matched", never "unused". To find baselines no test writes at all,
move the directory aside and let a full run recreate it; whatever is missing
afterwards is an orphan (cross-check against tests that failed in that run).
