    2. Portal sign-in —

    Credentials go to the stand backend only and are used to call the portal API (client management). An admin/owner account also lets the stand auto-configure the SDK CSP list.

    3. OAuth client —

    The portal returns the client secret only once, at creation time — so the stand always works with its own clients: create one here, reuse it across restarts, delete it when done. Redirect URI, allowed origins, URLs, logo and CSP are configured automatically.

    4. Authorize —

    You will sign in on the portal and pass the consent screen. Right after the token exchange the stand wipes the portal cookies (asc_auth_key & co) for localhost — everything below runs on the OAuth Bearer token alone.
