## 11. Owed by the .NET side (not tracked here)

These come from proposal.md ("Server work this change depends on"). They are owned by `../server` C# and listed so the tasks above are not mistaken for the whole job. None of them is a statement of what the server does today; what has landed is in proposal.md.

- List all of a user's conversations with their agents in one call (a list without a scope answers the threads of no project only).
- Copy a portal file into the thread's attachments folder on the server: server 581104bef6 lets a member copy a file into the agent's room as an attachment, but ASC.AI.Chat still reads and re-uploads the file (up to 50 MB) instead of asking for that copy. Remove the copy of a file that was attached and never sent. The thread folders are no longer visible to the other members: since server 1741b043ae a file inside an agent is its author's alone.
- Clean the attachments of deleted files, not of deleted folders: `DeleteAttachmentsByFolderIdsAsync` matches the attachments' file ids against the ids of the deleted folders, so deleting a folder drops the attachments of an unrelated file with the same number.
- Repair a thread whose folder was deleted (the stored folder id is returned unchecked). The files of a deleted thread are removed by a background pass since server aa4b63e038.
- ~~Count a member who joined through a group as a member~~: since server d2e3fe02c9 a group cannot be a member of an agent.
- Tell the author of a thread about a new artifact or attachment over the socket, so Content need not stand in for it with the chat's round events.
- Confirm whether a DocSpace admin's `removeSecurityInfo` on an agent deletes every member's conversations (design.md, Open Questions).
- Save the documents the .NET editor tools create (`EditorToolsFactory`) among the artifacts of the thread.
- "Used by", a description and portal-wide access for skill sets and knowledge bases, and the time a knowledge base was last indexed (boards 11 and 14); the reason a file failed to index (board 15); the template a room was installed from (the "Already added" mark of board 04).
- Store an agent's description and return it with the agent in the list.
- Word the texts the server composes for agents: notification e-mails, history entries, error messages, the role names.
- Store an agent's instructions: the template installation writes them to `files/rooms/{id}/instructions`, which no route in `../server` serves, so an installed agent comes without them (`instructionsNotSaved`).
- Say where the agent's instructions and suggestions, which the client reads at `files/rooms/{id}/instructions` and `files/rooms/{id}/suggestions`, are served.
